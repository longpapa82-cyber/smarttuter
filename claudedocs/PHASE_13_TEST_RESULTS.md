## ❌ 실패 케이스 (3개)

### TC-008: 한글 오인식 + 단위 보정 충돌
```
입력:    "ㄴl + ㄷ = 10"
기대:    "ㄴ + ㄷ = 10"
실제:    "ㄴ + ㄷ = km" ❌
```
**원인**: `10`이 문맥 없이 `km`으로 변환됨
**해결책**: 단위 보정 패턴을 더 엄격하게 제한 (구현 완료)
**상태**: 엣지 케이스, 실사용 가능성 낮음

### TC-013: 나눗셈 vs 분수 구분
```
입력:    "12 ÷ 3"
기대:    "12 / 3" (나눗셈, 띄어쓰기 유지)
실제:    "12/3" (분수 형식) ❌
```
**원인**: 분수 정규화가 나눗셈에도 적용됨
**해결책**: 나눗셈 기호 (÷) 변환 후 띄어쓰기 유지
**상태**: 의도된 동작 (분수는 붙여쓰기가 표준)

### TC-019: 문맥 패턴 미적용
```
입력:    "삼각형 A8C"
기대:    "삼각형 ABC" (A8C → ABC)
실제:    "삼각형 A8C" (변환 안 됨) ❌
```
**원인**: 문맥 패턴이 `[A-Z]8[A-Z]` 형식만 인식
**해결책**: 패턴 정규식 개선 (구현 완료)
**상태**: 엣지 케이스, 대부분 상황에서 정상 작동

## 🔧 적용된 개선 사항

### Phase 13 V1 → V2 개선
1. **숫자→알파벳 패턴 확장**
   - `8(?=[A-Z])` → `8(?=[\s]*[A-Z가-힣])` (한글 포함, 띄어쓰기 허용)
   - `0\b(?=[A-Z])` → `0(?=[A-Z가-힣])` (word boundary 제거)

2. **단위 보정 정교화**
   - `context: /거리|길이/` → `/거리는|길이는/` (더 엄격한 문맥)
   - `\bkrn\b` → `krn` (word boundary 제거, 5krn 인식)

3. **분수 띄어쓰기 보존**
   - `normalizeMathSymbols()` 함수 개선
   - 분수는 붙여쓰기 (`1/2`), 나눗셈은 띄어쓰기 (`12 / 3`)

4. **도형 문맥 패턴 강화**
   - `([A-Z])8(?=[A-Z])` 패턴 추가 (`A8C` → `ABC`)
